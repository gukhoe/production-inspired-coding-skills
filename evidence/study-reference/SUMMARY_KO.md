- 제공된 요청 문장은 10개 프롬프트 파일에서 동일하게 유지했습니다. 출력 함수/API/JSON 형식을 강제하지 않았습니다. 각 세션이 자연스럽게 만든 함수에 입력을 전달하고 결과의 표기만 정규화했습니다. 참가자 계산 로직은 수정하지 않았습니다.

- 공통 시간 제한 300초와 수정 제한 10회는 지시 수준이며 토큰 상한은 확인할 수 없었습니다. A도 공통 코딩 지침을 받으므로 순수 무지침 일반 ChatGPT와 동일하지 않습니다.
- 1회차는 행정 지시를 세션 시작 메시지에 직접 제공했고 2·3회차는 같은 본문을 각 폴더의 파일로 전달했습니다. 과제 요청·처치·예산은 그대로였고 각 반복의 A/B/C에 동일한 전달 방식을 썼지만, 추가 파일 읽기가 생긴 편차를 기록했습니다.
- 동일 시점에 최대 6개 세션을 시작하는 방식과 사전 무작위 순서를 사용했습니다. 일부 세션이 빨리 끝나 동시 부하는 변동했으며 실제 실행 스케줄링을 통제하지 못했습니다.
- 수정 횟수는 로그에 남은 Python 해시의 실행 간 변화입니다. 모든 편집 횟수나 실제 모델 호출 수는 알 수 없습니다. 자기보고와 직접 로그로 확인한 항목을 구분했습니다.
- 기존 구매 저장소는 열거나 수정하지 않았습니다. 외부 유료 API 키 생성·사용도 하지 않았습니다.
