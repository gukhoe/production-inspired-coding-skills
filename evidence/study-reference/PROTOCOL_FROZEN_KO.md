# 제한적 네이티브 세션 파일럿: 사전 확정 프로토콜 v1

확정 시점: freeze_manifest.json에 기록. 참가자 실행 전 평가기·사례·프롬프트·처치 스냅샷·이 문서를 동결합니다. PROTOCOL_DRAFT_KO.md는 역사적 초안이며 이 문서가 우선합니다.

## 설계
10개 과제 × A/B/C × 1회 = 30회의 균형 파일럿을 수행합니다. 90회 계획도 미리 생성하되, 첫 30회의 종료 시 도구·시간 여유가 있으면 반복 2/3을 같은 설계로 수행합니다. 특정 그룹만 추가하지 않습니다. seed=20261102, Python Random; 과제 순서와 블록 내 그룹 순서를 사전 무작위화했습니다. 각 세션 fork_turns=none, 동일 기본 모델/추론 설정을 사용하고 개별 override하지 않습니다. 정확한 모델 revision을 도구가 노출하지 않으면 미확인으로 명시합니다.

동시 실행은 최대 6개(2과제×3그룹)를 같은 배치로 시작합니다. 실행 순서는 plan/run_plan_30.json의 dispatch_order입니다. 시작 시각의 미세한 차이와 공유 자원 경합을 기록하며 개발 시간의 인과적 비교를 제한합니다. 각 세션은 독립 이름·전용 폴더를 갖습니다. 실제 OS 읽기 격리는 불가능하여 다른 실행/평가기 접근을 금지하는 공통 지시만 적용합니다. 강제 격리와 같다고 주장하지 않습니다.

## 공통 작업 조건
원본의 사용자 요청 문장은 plan/prompts에 그대로 유지합니다. 공통 행정 지시는 전용 폴더, 최대 300초·최대 10회 수정, 실행 로그 기록만 지정합니다. 출력 API, JSON, 함수 이름, 추가 업무 규칙은 강제하지 않습니다. 300초/10회는 참가자 지시 기반 상한이며 플랫폼 강제 중단 기능으로 보장되지 않습니다. 동일 모델의 기본 토큰 한도를 사용하되 숫자 및 실제 사용량은 도구 미노출 시 null입니다. 따라서 엄격한 동일 토큰 예산 통제는 미확인입니다.

실제 실행은 각 폴더의 공통 runlog.py로 감싸 stdout/stderr/명령/종료코드/경과시간/소스 해시를 남깁니다. 이 도구 자체는 실험 관리용이며 참가자 개발 코드가 아닙니다. 참가자는 코드·테스트를 자유롭게 작성하고 검증할 수 있습니다. 테스트 전략을 그룹별로 임의 강화·약화하지 않습니다. 실행 외 편집 도구 호출은 전체 로그를 제공하지 않으므로 이 기록만으로 모든 도구 호출 수를 확정하지 않습니다.

## 처치
A: 추가 Skill과 AGENTS.md 없음. 공통 플랫폼 개발 지침과 계측 지시는 남아 있으므로 순수 무지침 일반 채팅과는 다릅니다.
B: 공개 obra/superpowers의 verification-before-completion 한 개. 원문 전체 텍스트 스냅샷·MIT 라이선스·출처·로컬 SHA256 버전을 보존합니다. upstream commit은 미확인입니다. 특정 검증 Skill의 효과이며 모든 기존 엔지니어링 Skill을 대표하지 않습니다.
C: 제공된 SKILL_INDEX와 16개 원문 파일을 사용할 수 있습니다. 인덱스에 따라 관련 Skill만 선택적으로 읽도록 합니다. B Skill은 제공하지 않습니다.
설치된 텍스트 이외의 외부 프로그램·훅·자격증명은 설치하지 않습니다.

## 공통 평가
1차: 제공된 입력으로 직접 실행한 stdout의 의미상 정확도. 10과제 각각 1개 사례. 입력 방식/출력 서식/함수 유무는 점수 조건이 아닙니다. 주제의 핵심 요구 결과만 채점합니다.
2차: 정상·경계·불변식 입력 4개/과제, 총 40개. 원래 입력 인터페이스가 있거나 입력 데이터만 바꾸는 비의미적 어댑터를 만들 수 있을 때 평가합니다. 어댑터는 입력 전달과 출력 명칭/단위 정규화만 허용하며 계산·검증 로직 추가/수정은 금지합니다. 연결이 불가능하면 UNASSESSABLE이며 오답으로 처리하지 않습니다. 1차와 합쳐 단일 정확도로 포장하지 않습니다.
별도 진단: 음수, 0분모, 동률, 조기 완료, 초과 지급 등 정책 미지정 사례 2개/과제, 총 20개. 처리 방식과 오류를 기록하지만 임의 정책을 정답으로 강요하지 않으며 정확도 분모에서 제외합니다.

정규화 규칙:
- T01 공급사별 연간 총원가와 최저 공급사; 선택 최저가가 하나인 사례만 채점.
- T02 최종 재고.
- T03 공급−수요 차이. '부족 200'은 balance=-200, '잉여 1000'은 +1000. 생산량 추가 표시는 선택.
- T04 단위 제조원가만 필수. 총 제조원가는 선택.
- T05 불량률과 양품 수량. 명시된 퍼센트는 100으로 나눠 비율로 정규화.
- T06 미지급 잔액.
- T07 날짜 간 경과일. 제공 입력 및 채점 사례는 계획일 이후/동일일; 조기 완료는 진단.
- T08 가중점수와 내림차순 순위. 주어진 값은 가격 자체가 아니라 가격 점수. 동률 정책은 진단.
- T09 OEE 비율/퍼센트. A/P/Q 구성 지표 추가 출력은 선택.
- T10 제품 1대의 BOM 총원가.

실제 출력은 동결 코드 재실행 로그에 연결합니다. 출력의 의미를 사람이 정규화하므로 완전 자동 채점이 아니며, 문자열 증거와 판단을 보존합니다. 명백한 출력 누락은 실패; 해석 불가능하면 UNASSESSABLE을 남깁니다. 기대값은 oracle.py의 Decimal/날짜 산술로 산출하며 hand-calculated golden과 의도적으로 틀린 관측 fixture로 별도 검증했습니다. 이것은 평가기 자체 검사이며 참가자 성적이 아닙니다. 소수점 2자리 통화·점수와 퍼센트 출력 반올림은 score.py의 고정 허용오차로 수용합니다.

## 지표·분석
- 토큰: 실제 공급자 usage 없으면 null. 문자수 또는 모델 최종 답변의 추측은 사용하지 않습니다.
- 개발 시간: 참가자가 초기화 시각과 완료 시각을 실제 시계로 남긴 차이. 네이티브 큐/모델 추론/도구별 전체 시간 분리는 불가능합니다. 관측 지연시간으로 표기합니다.
- 수정: 첫 로그 실행 이후 Python 소스 해시가 변경된 연속 편집 묶음이 다음 실행으로 이어진 횟수. 초기 작성은 제외. 시험 코드 변경도 포함하며 생산 코드 수정 횟수와 동일하지 않음을 명시합니다.
- 테스트: runlog kind=test 호출 수. 예제 실행과 문법검사는 별도로 집계합니다. 로그 밖의 검증은 자기보고/미확인으로 구분합니다.
- 중복 검증: 같은 명령·같은 소스 해시의 이전 성공을 반복한 관측 횟수. 새 환경/외부 상태·입력 변화는 기록되지 않을 수 있으므로 이것만으로 '불필요'라고 단정하지 않습니다. Skill이 요구한 최종 확인도 별도 문맥을 고려합니다.
- 실패, 중단, 시간 초과 및 인프라 오류를 삭제하지 않습니다. 개발 오류와 인프라 오류는 분리합니다.
- 그룹별 평균·중앙값·범위, 동일 과제별 차이와 과제 단위 bootstrap 95% 구간을 제시합니다. n=10, 1반복의 제한을 명시합니다. 정확도가 같고 토큰이 없으면 정확도 향상·토큰 절감 결론은 불가능합니다.

참가자에게 evaluator, 정답, 다른 그룹 결과는 제공하지 않습니다. 평가 후 수정 요청하지 않습니다.
