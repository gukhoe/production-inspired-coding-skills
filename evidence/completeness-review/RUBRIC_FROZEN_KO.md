# 최종 코드 완성도 추가 검토 기준 v1

고정 시각: 2026-11-02T23:48:00Z. 이번 검토는 기존 실험 후 실시하는 사후 정적 리뷰이며 새 독립 생성 실험이 아니다. 원본 코드를 수정하지 않는다. 요구되지 않은 GUI/API/배포/데이터베이스 기능을 감점하지 않고 코드 길이·문서량·클래스 수에 가점을 주지 않는다.

원래 요청의 필수 충족(M): 제공 입력으로 실행 가능한 Python 코드, 요청 계산/선정/순위/출력. 기존 실행 증거와 정적 확인으로 PASS/PARTIAL/FAIL만 표시한다. 유지보수 개선 점수와 합산해 필수 충족의 의미를 바꾸지 않는다.

선택적 유지보수 준비도: 각 차원 0/1/2. 0=해당 개선 증거 없음 또는 명확한 결함, 1=작은 과제의 기본 수준, 2=그 범위 안에서 명확한 추가 유용성. 낮은 점수는 원 요청 실패를 뜻하지 않는다. 사실 증거와 함수/파일을 함께 기록한다. 전체 총점은 만들지 않는다.
- 구조/가독성 S: 0=흐름·이름·결합이 명확히 이해를 방해; 1=간결하고 이해 가능한 절차/함수; 2=계산과 예제/입출력 분리, 명확한 이름과 정책 설명. 복잡한 추상화는 이점이 확인되지 않으면 가점하지 않음.
- 재사용 R: 0=입력/계산을 바꾸려면 로직 편집 필요; 1=호출 가능한 계산 함수 또는 입력만 교체 가능; 2=함수 인자가 입력을 받고 결과를 반환하며 import에 예제 실행 부작용이 없음. JSON CLI는 필수가 아님.
- 오류/경계 E: 0=객관적으로 잘못된 값에 잘못된 결과/설명 없는 실패, 또는 검증 증거 없음; 1=일부 관련 오류/경계 처리 또는 정책 명시; 2=주요 객관적 오류(예: 0분모, 잘못된 날짜, 부적절한 타입/누락 필드 등)를 설명 가능하게 처리하고 핵심 유효 경계도 다룸. 업무 정책이 미지정인 음수/초과지급/조기완료는 허용·거절 어느 쪽도 자동 감점하지 않음. 유효 입력 범위를 과도하게 제한하면 별도 지적.
- 자체 테스트 T: 0=독립 기대값의 assertions가 없음(예제 출력만); 1=assert로 정상 계산을 확인; 2=정상 확인에 더해 의미있는 경계/불변식/오류 정책 검사를 확인. 횟수/케이스 수 대신 검증의 구체적 의미를 평가. 테스트가 코드를 그대로 베끼거나 잘못된 oracle이면 별도 지적.
- 사용/실행 문서 D: 0=실행 방법/입력/출력 의미 파악 어려움; 1=이름·예제·main 구조로 기본 실행과 출력 의미 확인 가능; 2=간단한 명시적 실행법 또는 함수 인자/반환/단위/정책 문서가 있어 수정·재사용이 더 쉬움. README 파일 자체는 필수 아님.

그룹 정보는 코드 읽기 단계에서 가능한 한 숨기되 코드 자체가 Skill 사용 흔적을 드러낼 수 있고 평가자는 이전 집계 결과를 알므로 완전 맹검이라고 주장하지 않는다. 산출물별 독립 평정 후 과제×그룹 3반복의 차원별 평균 및 사례를 제시한다. 10개 작은 산술 문제에 대한 사후 질적 평가이며 점수의 통계적 유의성·일반적 인과 효과를 주장하지 않는다.
